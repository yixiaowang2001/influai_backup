# 热门评论筛选逻辑

帖子ID（必填）、父评论ID（可以为空，如果是空，则就是处理帖子下的所有一级评论；如果不为空，则处理当前父评论下的所有子评论）、筛选数量（可以为空，默认为10）。评论的文本和态度，都可以通过父评论ID和帖子ID从数据库里拿

1. 筛选：选择同层级重要评论
   1. 参数：
       1. 所有同层级评论
       2. 筛选系数（系数 * 总评论数）
   2. 逻辑：
       1. 根据态度决定系数1：极端态度系数高（BAD、PERFECT、GOOD） - 0.8～0.9；中立 - 0.3；友善、不友善 - 0.1
       2. 根据评论长短决定系数2：越长概率越高
       3. 输出筛选出来的评论（按系数排序）
2. 验证一下筛选结果，不行就考虑大模型

# 生成lvn评论逻辑

1. 广度生成：基于上一层级的评论生成多条同级子评论（不同态度的）
    1. 参数：
        1. 人设
        2. 帖子ID（获取帖子内容）
        3. 上级评论ID（获取评论态度、评论内容、上级评论是否是人类用户、上级评论的上级评论（如果有））
        4. 重试次数（默认=5）
    2. Prompt包含：考虑到帖子内容和人设，上级评论的态度和内容等信息，生成不同态度的评论（以意见完全一致和意见完全不一致为主）；如果上级评论为人类用户，做出不同的反应；生成数量由大模型决定，确保衰减
2. 深度生成：基于上一层级的评论生成子评论对话（不同级）
    1. 参数：
        1. 人设
        2. 帖子内容
        3. 上级评论态度
        4. 上级评论内容
        5. 上级评论是否是人类用户【是否需要考虑】
        6. 上级评论的上级评论
        7. 对话深度【是否需要让大模型自定】
        8. 双人对话 / 多人对话
        9. 单层级是否生成多条
        10. 重试次数
3. 生成逻辑：
    1. 基于所有lv1，通过筛选选出有价值评论。
    2. 对于所有评论，进行lv2的广度生成。筛选重要评论，然后进行lv3的广度生成。
    3. 对于最有价值的评论，进行深度生成（默认多人对话、单层可以生成多条）。

# 评论推送逻辑

只有lv1和lvn中回复人类用户评论的帖子需要推送。（优先完成固定间隔推送）

1. 入参
    1. 完成时间
    2. 方法（固定间隔抖动 + 热度曲线）
    3. 固定间隔相关参数
    4. 热度曲线相关参数
2. 写一个方法，根据评论推送完成时间和评论数量，对于不同评论进行推送逻辑间隔设定。同时考虑到态度，优先PERFECT和GOOD（推送概率更高），然后其他概率一致（路人和黑粉）。
3. 支持两种模式的间隔设定，一种是固定间隔 +
   随机抖动；一种是热度曲线：模拟社交平台真实节奏——“先一小波、再逐步稀疏、留长尾”。用分段或指数衰减的到达过程安排推送时间。【目前看来固定间隔的方法比较实用，考虑到一次会推多条，用户其实对热度推送的感知不明确】
4. 在推送评论的过程中，每次推送的评论不一定只有一条，很多时候可以一起推送多条

# 点赞增长逻辑

1. 点赞增长场景分为三类：
    1. 用户发帖的点赞增长（包含推送）
    2. 用户评论的点赞增长（包含推送）
    3. AI用户评论的点赞增长（不包含推送）
2. 用户发帖点赞增长
    1. 固定间隔推送，但是点赞数量需要符合热度分布（一开始多之后少）
3. 用户评论点赞增长
    1. 同用户发帖【需要考虑点赞数量上限怎么决定】
4. AI用户评论点赞增长
    1. 评论发出后，基础自带0～3个赞
    2. 后台每隔1～5分钟给30%～50%的AI评论点赞N个（着重关注于情绪态度比较极端的情况：PERFECT和GOOD - 50%，BAD - 30%，其他 -
       20%）
    3. 热门评论每次点赞3～5 * N个，并且分到的点赞机会更大。
